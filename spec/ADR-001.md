# ADR-001 — Sintaxe Concreta de Lumen

**Status:** Aceito  
**Data:** 2026-09-13  
**Decisores:** Lumen Lang Team  
**Relacionado a:** `EBNF.md`, `SPEC.md` §4 D1/D2/D8/D10

---

## Contexto

Precisávamos definir sintaxe concreta para declarações de módulo, funções, bindings, controle, tipos e macros. Requisitos:

- Familiar para usuários de Rust/Go/Kotlin, mas sem ruído de `;` obrigatório em todo lugar e sem `package` verboso.
- Suporte a `module hello` / `import std.io` / `pub fn main() -> int` exatamente como nos exemplos canônicos.
- `let x: int = 42; let mut y = x + 1` com imutabilidade por padrão.
- `if x > 0 { } else { }` e `match v { 0 => "zero", _ => "outro" }` como expressões.
- `struct Ponto { x: float, y: float }` e `enum Opt { Nenhum, Algum(int) }` nominais.
- Macros com `!` e atributos `#[test]`.

Alternativas consideradas:

- **(A) Estilo Go:** `package hello`, `func main() int`, `var x int = 42`. Rejeitado: `var` não distingue mut, `package` confunde com diretório.
- **(B) Estilo Rust puro:** `mod hello; use std::io; fn main() -> i32`. Rejeitado: `mod`/`use`/`::` são ruidosos para iniciantes; `i32` vs `int` fragmenta.
- **(C) Estilo Lumen (escolhido):** `module`/`import`/`pub fn`/`let mut`/`match` com `=>`.

---

## Decisão

Adotar gramática `EBNF.md` com:

1. **`module` singular** no topo do arquivo (`module hello`), mapeando 1:1 para arquivo `hello.lm`. `import std.io` com `import A.{B,C as D}` e `import A.*`.
2. **Visibilidade `pub`** (privado por padrão). `pub(crate)`, `pub(super)` futuros. Funções: `pub fn main() -> int { ... }`.
3. **`let` / `let mut`** — imutável por padrão. `const` para constantes. Sem `var`.
4. **`if`/`else` e `match` expressões** — `match` com `=>` e `_` wildcard, exaustivo. `for v in iter`, `while cond`, `loop`.
5. **Tipos:** `int` (alias para `i64`), `float` (`f64`), `string`, `bool`, tupla `(T,U)`, record anônimo `{x: T}`, `fn(T)->U`, `&T`, `&mut T`.
6. **Declarações nominais:** `struct Ponto { x: float, y: float }`, `enum Opt<T> { Nenhum, Algum(T) }`, `trait` + `impl`.
7. **Genéricos:** `fn id<T: Clone>(x: T) -> T`, `where` clause.
8. **Async:** `async fn`, `expr.await` pós-fixo.
9. **Macros:** `macro nome { (pat) => (expansão) }` e invocação `nome!(args)` / `nome![args]` / `nome!{args}`. Builtins `println!`, `vec!`, `assert!`.
10. **Atributos:** `#[test]`, `#[bench]`, `#[derive(...)]`, `#[inline]` sobre itens. `//` e `/* */` comentários (bloco aninhável).

---

## Consequências

**Positivas:**

- Exemplos canônicos são válidos sem transformação: `module hello` ... `pub fn main() -> int` parseia.
- Curva suave: quem conhece JS/Rust lê Lumen; `let mut` é auto-explicativo.
- `match` exaustivo previne bugs; `struct` nominal evita confusão de unidades.
- `#[test]` co-localizado habilita `lumen test` sem config.

**Negativas:**

- `module` no topo é redundante com path do arquivo; exige verificação de consistência (lint).
- `int` vs `i32`/`i64` pode confundir usuários de Rust que esperam tamanho explícito; mitigado por aliases `i32` etc ainda válidos.
- `!` para macros exige digitação extra; mas distingue claramente compile-time.

**Migração:**

- Parser `compiler/frontend` implementa esta EBNF; testes de conformidade em `conformance/` validam.

---

## Exemplo Normativo desta ADR

```lumen
module hello
import std.io

pub fn main() -> int { io.println("olá"); return 0; }
let x: int = 42; let mut y = x + 1
if x > 0 { } else { }; match v { 0 => "zero", _ => "outro" }
struct Ponto { x: float, y: float }; enum Opt { Nenhum, Algum(int) }
```

Todos devem parsear segundo `EBNF.md` §2-11.
