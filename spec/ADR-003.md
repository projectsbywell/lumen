# ADR-003 — Ownership e Borrow Simplificado

**Status:** Aceito  
**Data:** 2026-09-13  
**Decisores:** Lumen Lang Team  
**Relacionado a:** `SEMANTICA.md` §3-4, `TIPOS.md` §9, `SPEC.md` §4 D6

---

## Contexto

Lumen almeja segurança de memória sem GC e sem expor lifetimes na maioria do código.

Opções:

- **(A) GC only (Go, JS):** simples, mas pausas, sem controle de recurso, ruim para WASM.
- **(B) Ownership explícito total (Rust):** seguro e zero-cost, mas lifetimes `<'a>` assustam e poluem assinaturas.
- **(C) Ownership invisível / elidido (escolhido):** semântica de Rust, sintaxe de Swift/Kotlin na maioria do código; `&`/`&mut` só quando empresta; lifetimes elididos.

Requisitos:

- `let s: string = "olá"; let t = s; // s movido` deve ser erro usar `s` depois (se `string` não é `Copy`).
- `let mut p = Ponto{...}; let r = &p; // borrow imut` deve bloquear `p.x = ...` enquanto `r` vivo.
- `Copy` para primitivos (`int`, `float`, `bool`, `char`) → cópia implícita, sem move.
- NLL (non-lexical lifetimes): borrow expira no último uso, não fim do bloco.

---

## Decisão

### 1. Modelo de permissões (SEMANTICA.md §3)

Cada localização `Addr` tem `Perm`:

```
Own | BorrowImm(n) | BorrowMut | Moved
```

- `Own` → dono único, pode mover, mutar se `mut`.
- `move(x)` → `Moved`, acesso posterior erro estático E038.
- `borrowImm(x)` → `BorrowImm(n+1)` se `Own` ou `BorrowImm`.
- `borrowMut(x)` → `BorrowMut` se `Own mut` e `n==0` e não `BorrowMut`.
- Fim de escopo → `drop` exige `n==0` e não `BorrowMut` (borrow checker).

### 2. `Copy` marker

```lumen
trait Copy {} // marker, sem métodos
impl Copy for int {}
impl Copy for float {}
impl Copy for bool {}
// string, Vec, Ponto NÃO são Copy → move
```

Se `T: Copy`, `let t = s` copia bits, `s` permanece válido. Checker insere `copy` vs `move` baseado em trait.

### 3. Borrow checker estático, checks dinâmicos na semântica

- **Estático:** `compiler/middle/borrowck` rejeita programas que violariam `Perm` (erro E050-E059). Garante soundness sem runtime cost.
- **Dinâmico:** `SEMANTICA.md` small-step inclui `Err(Borrow)` para especificação, mas programas bem tipados nunca atingem.

### 4. Elisão de lifetimes

- `fn foo(s: &string) -> &string` desugars para `fn foo<'a>(s: &'a string) -> &'a string` (um input → output herda).
- Múltiplos `&` inputs sem anotação → erro que pede anotação futura; hoje exige reescrita para `fn foo(a: &string, b: string) -> string` (pass by value move).
- Lifetime é escopo do borrow (NLL): expira no último uso.

### 5. Mutabilidade

- `let x = ...` → `Own immut`. `let mut x` → `Own mut`. `&x` → `&imm`, `&mut x` → `&mut`.
- `&mut T` invariante em `T` (não pode coagir `&mut Ponto` para `&mut {x:float,y:float}`).

---

## Consequências

**Positivas:**

- 80% do código nunca escreve `&`: `fn soma(a: int, b: int) -> int` passa por valor (Copy, sem borrow).
- `string` move previne cópias caras acidentais; `Copy` para primitivos mantém ergonomia.
- Borrow checker pega data races em `async` futuro (quando `Send`).
- Sem lifetime syntax para hello world; curva gradual.

**Negativas:**

- Elisão esconde custo: `fn foo(s: string) -> string` move string (pode ser caro) — precisa `&string` para emprestar, mas usuário pode não saber. Mitigado por clippy lint "pass by reference".
- NLL exige análise de fluxo mais complexa no borrowck.
- Mensagens de erro de borrow são inerentemente complexas; exige diagnostics ricos.

**Exemplo de erro:**

```lumen
let mut p = Ponto { x: 1.0, y: 2.0 };
let r = &p;
p.x = 2.0; // erro[E059]: não pode mutar `p` enquanto emprestado como `&p` em linha 2
// ajuda: borrow `r` expira após último uso; mova `p.x = 2.0` após `println(r.x)`
```

**Implementação:**

- `compiler/middle/borrowck` opera sobre MIR (após HIR), análise de fluxo com `Perm` lattice.
- `stdlib` marca `Copy` para primitivos; `Drop` para `Vec`, `string` (free).

---

## Exemplo Normativo

```lumen
let s: string = "olá";
let t = s;              // move
// io.println(s)        // ERRO E038 uso após move
let mut p = Ponto { x: 1.0, y: 2.0 };
let r = &p;             // borrow imut
let x = r.x;            // OK
// p.x = 3.0            // ERRO enquanto r vivo
drop(r); // fim de escopo
p.x = 3.0; // OK
```
