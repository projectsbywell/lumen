# ADR-002 — Sistema de Tipos: Nominal + Estrutural, Inferência e Genéricos

**Status:** Aceito  
**Data:** 2026-09-13  
**Decisores:** Lumen Lang Team  
**Relacionado a:** `TIPOS.md`, `SPEC.md` §4 D3/D4/D5, `SEMANTICA.md` §3

---

## Contexto

Lumen precisa de tipos que sejam:

- Seguros (sem `any` implícito, sem coerção silenciosa perigosa).
- Ergonômicos ( `let mut y = x + 1` sem anotação).
- Expressivos (genéricos + traits para coleções, async).

Tensões:

- **Nominal puro** (Rust, Java) é seguro para domínio, mas verboso para dados ad-hoc (JSON, configs).
- **Estrutural puro** (TypeScript, Go interfaces) é flexível, mas perde identidade de domínio (`Ponto` vs `Vetor` confundem).
- **Inferência global** (Haskell) dá erros crípticos; sem inferência (Go) verboso.

Alternativas:

- (A) Só nominal → rejeitado: `fn norma(p: {x:float,y:float})` precisaria `struct` temporário.
- (B) Só estrutural → rejeitado: `struct` perde distinção, quebra invariantes.
- (C) Híbrido com subtipagem controlada (escolhido).

---

## Decisão

### 1. Híbrido

- **Nominais:** `struct`, `enum`, `trait` criam identidade por `Crate::Nome<args>`. `Ponto` ≠ `{x:float,y:float}` e ≠ `Vetor` mesmo com mesmos campos. Compatibilidade só via `as` explícito ou trait comum.
- **Estruturais:** `()`, `(T,U)`, `fn(T)->U`, `[T]`, `[T;N]`, `{l:T}` (record anônimo). Comparados por forma. Subtipagem por **largura** para records: `{x,y,z} <: {x,y}`.

### 2. Inferência bidirecional

- **Síntese** `Γ ⊢ e ⇒ τ` e **checagem** `Γ ⊢ e ⇐ τ`. Let-polymorphism (generaliza em `let`, não em lambda).
- Assinaturas `pub fn` exigem tipos; `let` local pode omitir (`let mut y = x + 1` ⇒ `int` via `Add`).
- Hole `_`: `let x: _ = 42` → infere `int`.

### 3. Subtipagem

- Records: largura + profundidade (covariante se campo `imm`, invariante se `mut`).
- Funções: contravariante em params, covariante em retorno.
- Arrays: `[T;N]` coerção para `&[T]`.
- `!` (never) é subtipo de tudo. `null` só para `Opt<T>`.

### 4. Genéricos + Traits + Where

- `fn max<T: Ord>(a: T, b: T) -> T where T: Clone`
- Tipos associados `I::Item`, `where I: Iter`.
- Coerência orphan: impl deve estar no crate de `trait` ou `Self`.
- Monomorfização para `native`/`wasm`, dict-passing para `vm`.

### 5. Variância

- Inferida por uso: `Opt<T>` covariante, `Vec<T>` invariante (por `&mut T` interno), `fn(T)` contravariante. Futura anotação `in`/`out`.

---

## Consequências

**Positivas:**

- `let p: {x:float,y:float} = {x:1.0,y:2.0}` funciona sem declarar `struct`; `struct Ponto` protege domínio.
- `len({x:1,y:2,z:3})` onde `len: fn({x:float,y:float})->float` aceita por largura — genérico útil.
- Erro local: `let x: int = "olá"` → `esperado int, encontrado string` na linha.
- Genéricos sem GC overhead quando monomorfizado.

**Negativas:**

- Dois sistemas aumentam complexidade do checker (nominal env `Σ` + estrutural).
- Subtipagem largura pode surpreender (`{x,y,z}` aceito onde `{x,y}` esperado) — mitigado por `exact` annotation futura se necessário.
- Monomorfização aumenta tamanho binário; dict-passing em `vm` tem custo.

**Implementação:**

- `compiler/middle` contém `typeck` com `unify` + `subtype` + `trait solve`.
- Testes: `conformance/tipos/` validam `Ponto` ≠ record, largura, inferência `y = x+1`.

---

## Exemplo Normativo

```lumen
struct Ponto { x: float, y: float }
struct Vetor { x: float, y: float }
let a: {x: float, y: float} = {x:1.0, y:2.0}; // estrutural OK
// let b: Ponto = a // ERRO nominal
fn dist(p: {x: float, y: float}) -> float { return p.x + p.y; }
let c = {x:1.0, y:2.0, z:3.0};
dist(c) // OK por largura
fn id<T: Clone>(x: T) -> T { return x.clone(); }
```
